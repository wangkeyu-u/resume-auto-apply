# 大规模数据"训练"成果报告 · 简历自动投递系统

> 生成日期：2026-07-12
> 对应需求：用户要求"用大量的数据帮我训练……要有正面价值"
> 落地方式：**联网抓取真实 JD → 归纳 → 结构化岗位知识库（RAG 检索增强）**，而非微调模型

---

## 1. 为什么用"知识库"而不是"微调模型"

| 维度 | 微调大模型 | 结构化岗位知识库（本次采用） |
|---|---|---|
| 可行性 | 本地算力/数据/合规门槛高，得不偿失 | 立即可行，纯数据工程 |
| 可解释性 | 黑盒，难审计 | 每条要求可溯源到真实 JD |
| 可迭代 | 重训成本高 | 改 JSON / 重跑合并脚本即可 |
| 正面价值 | 不确定 | 分析"有据可依"，减少胡编 |

结论：把"训练"务实落地为**大规模、真实、可审计的领域知识库**，让简历分析与优化的每一步都对着市场真实要求，而不是模型凭空生成。

## 6. 如何复现 / 重建知识库

```bash
# 在 resume-auto-apply 目录下，使用 managed venv
unset http_proxy https_proxy
<managed-venv>/python scripts/build_knowledge.py
```

重建后会刷新 `data/jd_knowledge.json` 的 `_meta`（版本、角色数、关键词宇宙），`app/tailor.py` 在导入时自动从知识库派生 LEXICON，无需改代码。

---

## 7. 红线与合规（保持）

- **不代点 BOSS 直聘等站点的"真正发送"**（无官方 API + 封号风险）。
- 邮件通道可全自动；BOSS 仅自动拟稿，最后发送仍由人工确认。
- 默认**不自动拉黑**公司，需用户显式触发。
- 知识库内容均来自公开招聘信息归纳，仅用于提升分析质量，无违规抓取或滥用。
